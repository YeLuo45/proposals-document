## 1. 概念与愿景

多个 AI persona 在同一个对话线程里互相讨论、辩论、协作。用户作为主持人发起话题，各 persona 根据自己的性格设定发表观点、回应彼此，形成真正的多角色圆桌讨论。区别于传统聊天机器人单回合对话，这是"AI 社交"场景。

---

## 2. 设计方向

### 核心交互

1. **发起讨论**：用户在 Team 面板输入话题，选择参与的 persona（至少2个）
2. **圆桌讨论**：各 persona 按顺序发言，每个发言带有角色头像和名字气泡
3. **实时打字指示**：每个正在"思考"的 persona 显示 TypingIndicator
4. **用户干预**：用户可以随时插话、提问、或改变话题方向
5. **讨论总结**：讨论结束后自动生成要点总结

### 多人对谈消息结构

```typescript
interface MultiPersonaMessage {
  id: string;
  personaId: string;
  personaName: string;
  personaAvatar?: string;   // emoji 或图标
  content: string;
  timestamp: string;
  isUser?: boolean;         // true = 用户发的
  emotion?: string;         // 当前情绪状态
}
```

### 消息气泡 UI

- 左侧头像区：persona 的 emoji 头像（圆形）
- 中间气泡：背景色按 persona 区分
- 底部：情绪小图标 + 时间戳
- 用户消息：右对齐，气泡颜色区别

## 4. 技术方案

### 复用现有服务
- `personaService.ts` — 获取 persona 列表和 system prompt
- `chatCompletion` — AI 对话生成
- `emotionDetector` — 情绪检测
- 现有 `MultiPersonaCollaboration.tsx` 组件（已有团队 UI 基础）

### 讨论流程
1. 用户选择话题 + persona 列表
2. 为每个 persona 构造 system prompt（注入角色设定）
3. 轮流调用 `chatCompletion`，每次带上历史消息 + 当前 persona 的 prompt
4. 将 AI 回复追加到消息流
5. 情绪检测 → 显示情绪标签

### 消息存储
- 复用 `useStore` 的 messages 或新建 `discussionMessages`
- 每个 discussion 独立存储，支持切换

### 实现位置
- `src/components/MultiPersona/MultiPersonaCollaboration.tsx` — 扩展现有组件
- `src/services/discussionService.ts` — 新建讨论逻辑服务
