# PRD: PixelPal V64 — Agent执行循环闭环

## 1. 概述

**版本**: V64
**提案ID**: P-20260509-001
**类型**: 功能迭代（直接master）
**日期**: 2026-05-09

## 2. 背景

V54搭建了TaskQueue/AgentPanel框架，但Agent执行循环未完全闭环。当前状态：
- TaskQueue: 任务入队/出队/状态管理（单例）
- AgentPanel: 任务创建UI + 开始/暂停控制
- TaskCard: 任务卡片展示
- TaskConfirmDialog: 任务确认弹窗（ChatPanel集成）

**缺失环节**：
1. 任务启动后无实际AI执行逻辑
2. 任务步骤（steps）从未被AI填充
3. 任务完成后无结果汇总
4. AgentPanel的"开始下一个"只是从队列取出，未触发真正的AI处理

## 3. 目标

让Agent真正能够：
1. 接收用户目标 → 拆解为步骤
2. 按步骤执行 → AI调用 + 结果写入
3. 步骤推进 → currentStepIndex递增
4. 全部完成后 → 生成结果摘要 → 通知用户

## 4. 功能需求

### 4.1 Agent执行引擎（核心）

新增 `src/services/agent/agentExecutor.ts`：

```typescript
interface AgentExecutor {
  executeTask(taskId: string): Promise<void>;
  pauseTask(taskId: string): void;
  resumeTask(taskId: string): void;
  cancelTask(taskId: string): void;
}

// 执行流程：
// 1. 从taskQueue取出任务，status: 'running'
// 2. 调用 LLM（chatCompletion）分析目标，拆解步骤写入 task.steps
// 3. 逐条执行步骤：
//    a. 当前步骤 status: 'running'
//    b. AI调用（携带上下文）处理本步骤
//    c. 结果写入 steps[stepIndex].result
//    d. progress 更新
//    e. currentStepIndex++
// 4. 全部完成后：status: 'completed'，生成 summary
// 5. 触发通知（可选：桌面通知或聊天区消息）
```

### 4.2 步骤执行结果注入

每个步骤执行后，结果需要：
- 写入 `task.steps[stepIndex].result`
- 通过 `onTaskProgress` 回调更新UI
- 最终汇总写入聊天区（类似V54的TaskConfirmDialog逻辑）

### 4.3 AgentPanel状态联动

修改 `AgentPanel`：
- "开始下一个"按钮触发 `agentExecutor.executeTask()` 而非仅取出任务
- 显示当前执行中任务的实时进度（progress + currentStep/steps.length）
- Running状态的任务卡片高亮展示

### 4.4 任务状态持久化

任务队列状态存入IndexedDB（复用V55的persistence服务）：
- 页面刷新后任务队列不丢失
- Running状态任务刷新后可恢复（重新attach到executor）

## 5. 技术方案

### 5.1 新增文件

|------|------|

### 5.2 修改文件

| 文件 | 修改内容 |
|------|---------|
| `src/services/agent/taskQueue.ts` | 增加事件发射（taskStart/stepComplete/taskComplete） |
| `src/components/Agent/TaskCard.tsx` | 显示步骤进度、执行中状态高亮 |
| `src/components/Agent/AgentPanel.tsx` | 绑定executor，"开始"按钮触发真实执行 |

### 5.3 依赖

- 复用现有 `ChatPanel` 的 `chatCompletionWithTools` 服务
- 复用 `pluginRegistry` 的插件执行能力（步骤中可调用插件）

## 6. 非目标（不做什么）

- 不改 `TaskConfirmDialog` 的现有交互
- 不改 `pluginRegistry` 架构
- 不做多Agent并行执行（V65+再考虑）

## 7. 验收标准

1. 创建任务 → 点击"开始" → 任务状态变为running → AI开始拆解步骤
2. 步骤执行时，TaskCard显示 progress: X/Y
3. 全部完成后，任务状态变为completed，结果摘要显示
4. 刷新页面后，pending/completed任务队列完整恢复
5. `npm run build` 成功
6. 控制台无Error
