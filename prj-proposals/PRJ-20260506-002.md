## 1. 背景与目标

### 1.1 为什么做多智能体协作

PixelPal 当前 V27 已实现 **Multi-Persona Debates**——多个 AI persona 顺序发言讨论一个话题。但这只是"多人对话"，不是"协作"。

**当前局限**：
- 多个 persona 按固定顺序发言，无法真正分工
- 没有共享任务上下文，一个 persona 不知道另一个在做什么
- 没有任务委托机制，无法说"你负责查资料，我负责总结"
- 没有冲突检测和共识机制

**hermes-agent 的启示**：
- `acp_registry/` + `collaboration/` 模块实现了多 Agent 通信协议（ACP）
- 支持任务委托、结果汇聚、状态同步
- 18 个独立模块通过 Registry 模式实现松耦合

### 1.2 V33 目标

在 V27 Multi-Persona Debates 基础上，构建**真正的多智能体协作框架**：

> **核心用例**：用户提出一个复杂任务（如"帮我分析最近一周的情绪变化并给出建议"），多个 persona 像一个团队一样分工协作——一个查记忆，一个分析情感曲线，一个生成建议——最终给出一致结论。

## 2. 核心功能设计

### 2.1 协作架构

```
User Request
     │
     ▼
┌─────────────────────────────────────┐
│  Orchestrator (调度者)               │
│  - 分解任务                         │
│  - 分发子任务                       │
│  - 汇聚结果                         │
│  - 生成最终回复                     │
└─────────────────────────────────────┘
     │
     ├──▶ Persona-A (记忆专家) ──▶ 检索相关记忆
     ├──▶ Persona-B (情感分析师) ──▶ 分析情绪曲线
     └──▶ Persona-C (建议生成器) ──▶ 生成行动建议
```

**与 V27 Debates 的区别**：

| 维度 | V27 Debates | V33 Collaboration |
|------|-------------|-------------------|
| 交互模式 | 顺序发言 | 并行/串行结合 |
| 任务分配 | 无（全员发言） | Orchestrator 分解分发 |
| 共享状态 | 无 | 共享任务上下文 |
| 结果汇聚 | 无（各自发言） | Orchestrator 汇总 |
| 冲突处理 | 无 | 投票/仲裁机制 |

### 2.2 核心模块

#### 2.2.1 Task Decomposer（任务分解器）

将用户请求分解为可并行的子任务：

```
输入："分析我这一周的情绪变化，给些建议"
输出：
  - subtask_1: { type: 'memory_retrieval', params: { timeRange: '7d' }, responsible: 'MemoryExpert' }
  - subtask_2: { type: 'emotion_analysis', params: { data: 'subtask_1.result' }, responsible: 'EmotionAnalyst' }
  - subtask_3: { type: 'advice_generation', params: { emotionData: 'subtask_2.result' }, responsible: 'Advisor' }
```

**Prompt 模板**：
```
你是一个任务分解专家。将用户的复杂请求分解成可执行的子任务。
每个子任务需要指定：
- type: 任务类型（memory_retrieval | emotion_analysis | advice_generation | web_search | code_execution）
- params: 任务参数
- responsible: 负责角色（MemoryExpert | EmotionAnalyst | Advisor | Researcher | Coder）

规则：
- 子任务之间如果存在数据依赖，需明确标注 dependency
- 尽量并行化独立任务
- 每个子任务描述不超过50字
```

#### 2.2.2 Shared Context（共享上下文）

所有 persona 共享同一个任务上下文，支持读写：

```typescript
interface SharedContext {
  taskId: string;
  userRequest: string;
  subtasks: Subtask[];
  results: Map<string, SubtaskResult>;
  conversationHistory: Message[];
  sharedMemory: {
    entities: Entity[];
    facts: Fact[];
    decisions: Decision[];
  };
}
```

**读写原语**（类 hermes-agent 的 trajectory）：

```typescript
// 读取
context.read('emotion_data');     // 读取情感数据
context.read('memory_results');   // 读取记忆检索结果

// 写入
context.write('analysis_summary', '正面情绪上升15%');  // 写入分析摘要
context.addEntity({ name: '用户', traits: ['忙碌', '焦虑'] });  // 添加实体
```

### 3.2 核心类型定义

```typescript
// services/collaboration/types.ts

export type TaskType =
  | 'memory_retrieval'
  | 'emotion_analysis'
  | 'advice_generation'
  | 'web_search'
  | 'code_execution';

export type PersonaRole =
  | 'MemoryExpert'
  | 'EmotionAnalyst'
  | 'Advisor'
  | 'Researcher'
  | 'Coder';

export interface Subtask {
  id: string;
  type: TaskType;
  description: string;
  params: Record<string, unknown>;
  responsible: PersonaRole;
  status: 'pending' | 'running' | 'completed' | 'failed';
  result?: unknown;
  error?: string;
  dependencies: string[];  // 依赖的其他 subtask id
}

export interface SubtaskResult {
  subtaskId: string;
  role: PersonaRole;
  output: string;
  confidence: number;  // 0-1
  entities?: Entity[];
  facts?: Fact[];
}

export interface CollaborationSession {
  id: string;
  userRequest: string;
  subtasks: Subtask[];
  results: Map<string, SubtaskResult>;
  status: 'decomposing' | 'executing' | 'aggregating' | 'done' | 'failed';
  createdAt: number;
  updatedAt: number;
}

export interface CollaborationMessage {
  id: string;
  sessionId: string;
  role: PersonaRole;
  personaId: string;
  content: string;
  timestamp: number;
}
```

### 3.3 Orchestrator 核心流程

```typescript
// orchestrator.ts

export class CollaborationOrchestrator {
  async startSession(userRequest: string): Promise<CollaborationSession> {
    // 1. 创建 session
    const session = this.createSession(userRequest);

    // 2. 分解任务
    const subtasks = await this.decomposer.decompose(userRequest);
    session.subtasks = subtasks;

    // 3. 执行任务（拓扑排序 + 并行）
    await this.executeTasks(session);

    // 4. 聚合结果
    const finalResponse = await this.aggregator.aggregate(session);

    // 5. 保存到记忆
    await this.saveToMemory(session);

    return session;
  }

  private async executeTasks(session: CollaborationSession) {
    // 找出没有依赖的任务，并行执行
    const readyTasks = this.getReadyTasks(session.subtasks);
    await Promise.all(readyTasks.map(t => this.executeSubtask(t, session)));

    // 递归执行依赖任务
    const remaining = session.subtasks.filter(t => t.status !== 'completed');
    if (remaining.length > 0) {
      await this.executeTasks(session);
    }
  }
}
```

## 5. 验收标准

### 5.1 功能验收

| 用例 | 期望结果 |
|------|---------|
| 用户输入"分析我这周情绪" | 触发协作，三个 persona 分工完成 |
| 协作过程可视化 | 实时显示各 persona 状态 |
| 某 persona 执行失败 | 自动重试或跳过，结果仍可汇聚 |
| 切换回普通模式 | 原有单 persona 对话不受影响 |

### 5.2 非功能验收

- 协作完成时间 < 30秒（单次复杂任务）
- UI 不卡顿（异步执行）
- 向后兼容：V27 Debates 仍可用

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| LLM 调用次数增加（3x persona） | 成本上升 | 添加 max_tokens 限制，支持流式输出 |
| 协作过程语义冲突 | 结果质量下降 | 冲突仲裁机制，置信度加权 |
| 任务分解质量不稳定 | 子任务无法执行 | prompt 优化 + fallback 到简单分解 |
| 与现有 memory 服务耦合 | 改动范围大 | 通过 SharedContext 接口隔离 |
