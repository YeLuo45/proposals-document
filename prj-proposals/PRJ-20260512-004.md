# PRJ-20260512-004: PixelPal Provider Abstraction V81

## 1. Concept & Vision

Provider Abstraction 将 PixelPal 的 LLM 调用统一抽象为 Provider 接口，支持无缝切换 OpenAI/Anthropic/Gemini/本地模型/硅基流动等。参考 astrbot 的多Provider设计，让用户根据需求（速度/成本/能力）灵活选择模型。

## 2. Design Language

- 设置页面新增 "AI Providers" 区块
- Provider 配置卡片：图标+名称+状态指示灯
- 浅色主题卡片，与现有设置风格统一

## 4. Features & Interactions

### 4.1 Provider Interface

```typescript
interface AIProvider {
  id: string;
  name: string;
  icon: string;  // emoji
  status: 'connected' | 'error' | 'unconfigured';
  
  // Chat completion
  chat(messages: Message[], options?: ChatOptions): Promise<ChatResponse>;
  
  // Embeddings (for RAG)
  embed(texts: string[]): Promise<number[][]>;
  
  // Check connectivity
  ping(): Promise<boolean>;
}

interface ChatOptions {
  model?: string;
  temperature?: number;
  maxTokens?: number;
  stream?: boolean;
}
```

### 4.2 Supported Providers

1. **OpenAI** — GPT-4o, GPT-4o-mini, GPT-4-turbo
2. **Anthropic** — Claude 3.5 Sonnet, Claude 3 Opus, Claude 3 Haiku
3. **Google Gemini** — Gemini 1.5 Pro, Gemini 1.5 Flash, Gemini 2.0 Flash
4. **SiliconFlow** — 硅基流动（支持多种开源模型）
5. **Ollama** — 本地模型（Llama, Qwen, DeepSeek等）
6. **Custom** — 支持任意 OpenAI-compatible API

### 4.3 Provider Management

- **Add**: Configure new provider with API key + endpoint
- **Edit**: Update existing provider settings
- **Delete**: Remove provider (confirm if in use)
- **Test**: Send test request to verify connection
- **Set Default**: Choose default provider for all AI calls
- **Per-Chat Override**: Allow user to select provider per chat session

### 4.4 Model Registry

Each provider has a list of available models. When user configures a provider, available models are fetched or entered manually.

### 4.5 Fallback Chain

If primary provider fails (rate limit, network error), automatically try next provider in fallback chain. Configurable fallback order.

### 4.6 Cost Tracking (future)

- Track token usage per provider
- Display estimated cost in UI

### 6.3 Storage

```typescript
// Stored in localStorage
interface ProviderConfig {
  id: string;
  apiKey: string;
  baseUrl?: string;
  defaultModel: string;
  temperature: number;
  maxTokens: number;
  enabled: boolean;
}

interface ProviderSettings {
  defaultProviderId: string;
  fallbackOrder: string[];
  configs: Record<string, ProviderConfig>;
}
```

### 6.4 Integration

Existing `chatCompletion` from `model-registry-adapter.ts` should delegate to `providerManager.chat()`. Existing code should require MINIMAL changes if abstraction is done correctly.

### 6.5 API Implementations

Each provider implements the `AIProvider` interface using its native SDK or direct REST calls:
- OpenAI: `openai` npm package
- Anthropic: `@anthropic-ai/sdk`
- Gemini: `@google/generative-ai`
- SiliconFlow: REST (OpenAI-compatible)
- Ollama: REST (OpenAI-compatible)
