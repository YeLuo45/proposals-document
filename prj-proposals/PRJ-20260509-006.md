## 1. 背景与目标

当前项目存在**两套插件系统**：

| | PluginService | pluginRegistry |
|---|---|---|
| 位置 | `src/services/plugins/` | `src/services/plugins/registry.ts` |
| 创建时间 | V1早期 | V59 |
| 用途 | 工具调用（execute） | 工具注册（register） |
| API | `execute(tool, params)` | `register(handler)` |

**问题：**
- `agentExecutor.ts` 用 PluginService 执行工具
- 但 V59 新增的 `pluginRegistry` 没有被真正使用
- 两套系统并存造成维护负担和混淆

**目标：** 统一为一站式插件服务，同时保持向后兼容。

## 2. 现状分析

### 2.1 PluginService（现存）
```typescript
// src/services/plugins/pluginService.ts
class PluginService {
  execute(tool: string, params: any): Promise<any>
  getAvailableTools(): Tool[]
}
```

### 2.2 pluginRegistry（现存）
```typescript
// src/services/plugins/registry.ts
class PluginRegistry {
  register(config: PluginConfig): string  // 返回pluginId
  execute(pluginId: string, params: any): Promise<any>
  getPlugins(): PluginConfig[]
  unregister(pluginId: string): void
}
```

### 2.3 当前使用方
- `agentExecutor.ts` → 直接调用 `PluginService.execute()`
- 旧代码可能直接用 `PluginService.getAvailableTools()`

---

## 3. 统一方案

### 3.1 新建 UnifiedPluginService

在 `src/services/plugins/` 下新建 `unifiedPluginService.ts`：

```typescript
// 保留PluginService所有接口
class UnifiedPluginService extends PluginService {
  private registry: PluginRegistry

  // 合并两套注册接口
  register(config: PluginConfig): string
  registerLegacy(tool: string, handler: ToolHandler): void  // 兼容旧PluginService

  // 合并执行接口
  async execute(tool: string, params: any): Promise<any>
  async executeById(pluginId: string, params: any): Promise<any>

  // 合并查询接口
  getAllPlugins(): PluginConfig[]
  getTools(): Tool[]  // 兼容旧接口

  // 迁移辅助
  migrateFromRegistry(): void  // 将registry中的插件迁入unified
}
```

### 3.2 统一工具描述格式

所有插件统一使用 `Tool` 接口（来自 `agent/types.ts`）：

```typescript
interface Tool {
  name: string
  description: string
  params: ParamSchema[]
  handler: ToolHandler
}
```

### 3.3 迁移步骤

1. **第一阶段：并行运行**
   - `agentExecutor.ts` 改用 `UnifiedPluginService`
   - 原 `PluginService` 和 `pluginRegistry` 保留，标记 `@deprecated`

2. **第二阶段：迁移注册**
   - 将 `registry.ts` 中的插件迁移到 `UnifiedPluginService`
   - 移除 `registry.ts`

3. **第三阶段：清理**
   - 删除旧 `pluginService.ts`
   - 删除 `registry.ts`
   - 所有调用方统一使用 `UnifiedPluginService`

### 3.4 文件变更

```
src/services/plugins/
  unifiedPluginService.ts  — NEW：统一插件服务
  pluginService.ts         — @deprecated，代理到unified（临时）
  registry.ts              — @deprecated，迁移后删除
  index.ts                 — 更新导出unified
```

## 4. 验收标准

1. `agentExecutor.ts` 通过 `UnifiedPluginService` 执行所有工具
2. 现有工具（weather/search/calculator等）继续正常工作
3. 新注册工具可通过 `unifiedPluginService.register()` 接入
4. build通过：`npx vite build --mode production`
5. 无新增console.error
6. 旧接口 (`PluginService`, `pluginRegistry`) 标记 `@deprecated` 但暂不删除

---

## 5. 非功能需求

- 向后兼容：现有代码不改即可运行
- 单一数据源：工具列表只从 `UnifiedPluginService` 获取
- 可回滚：旧文件暂保留，commit message注明
